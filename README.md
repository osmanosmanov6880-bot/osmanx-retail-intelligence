# OSMANX RETAIL INTELLIGENCE

**Рабочий прототип аналитической платформы для магазинов одежды**. Премиальный адаптивный интерфейс на русском, опросник для выхода из магазина, учёт входов и продаж, журнал запросов на отсутствующие размеры, отчёты и рекомендации на основе прозрачных правил.

> **Статус:** R0.1 · локальный MVP. Демо-цифры синтетические. Публичное промышленное развёртывание, реальная интеграция 1С и физического счётчика входов **ещё не выполнены**.

## Запуск за 2 минуты

Требуется Python 3.11+ (рекомендуется 3.13). Node.js не нужен.

```bash
python -m venv .venv
source .venv/bin/activate                 # Windows: .venv\Scripts\activate
pip install -r requirements.txt
OSMANX_DEMO_MODE=1 uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

- **Кабинет директора:** <http://127.0.0.1:8000/>
- **Терминал для планшета:** <http://127.0.0.1:8000/kiosk/central>
- **Swagger (только демо):** <http://127.0.0.1:8000/api/docs>

Windows PowerShell:

```powershell
$env:OSMANX_DEMO_MODE="1"
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Демо создаёт в `data/retail.sqlite3` **искусственную** историю посещений, чеков, опросов и запросов. Новые события и отзывы сохраняются в SQLite. Чтобы начать заново, остановите сервер и удалите файл базы.

## Пять реализованных блоков

1. **Опрос на выходе:** отдельная сенсорная страница, оценка 1–5, факт покупки, причина отказа, необязательное мнение и финальный экран. Без сбора телефона/имени. Базовый rate-limit защищает от массовых отправок.
2. **Учёт посетителей и продаж:** ручные события, сохранение чеков, входы от датчика через API с ключом и `external_id` для идемпотентности. Конверсия = чеки / зарегистрированные входы; это не уникальные покупатели.
3. **Невидимый спрос:** фиксирование товара, размера, цвета, изменение статусов от «Открыт» до «Купил», статистика частых запросов.
4. **Кабинет:** тёмная адаптивная панель с фильтрами 7/30 дней, графиками, причинами отказов, карточками KPI, журналами и финансовым сценарным калькулятором.
5. **Хранение и API:** SQLite с индексами, FastAPI, административные Bearer-сессии в реальном режиме, JSON-импорт кассовых чеков с защитой от дублей, проверяемые правила рекомендаций, автотесты и CI.

## Настоящий режим (без демо)

**Не используйте `OSMANX_DEMO_MODE=1` в открытом интернете:** в демо административные API намеренно доступны без авторизации для локального знакомства с продуктом.

Создайте уникальные секреты (не сохраняйте их в Git):

```bash
export OSMANX_DEMO_MODE=0
export OSMANX_ADMIN_PASSWORD='ДЛИННЫЙ_УНИКАЛЬНЫЙ_ПАРОЛЬ_ОТ_12_СИМВОЛОВ'
export OSMANX_SESSION_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
export OSMANX_INGEST_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(32))')"
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Откройте адрес сервера, введите пароль администратора. При первом запуске создаётся пустой магазин `central`. Начните с ручного ввода данных или импорта чеков.

Для сетевого использования потребуется HTTPS, контроль доступа к терминалу, резервное копирование SQLite, защита от сетевых атак и настройка ролей. Текущий механизм авторизации рассчитан на одного владельца, не на распределённую сеть сотрудников. Открытый продакшен-деплой **не считается готовым**.

## API интеграций

### Счётчик входов

```http
POST /api/ingest/traffic
Content-Type: application/json
X-OSMANX-Ingest-Key: <OSMANX_INGEST_KEY>

{"slug":"central","quantity":1,"external_id":"sensor-2026-11-08-00001","occurred_at":"2026-11-08T12:00:00Z"}
```

Повторная отправка с тем же `external_id` не увеличивает счётчик.

### Импорт чеков из внешней POS/1С выгрузки

```http
POST /api/admin/import/pos
Authorization: Bearer <TOKEN_FROM_LOGIN>
Content-Type: application/json

{"slug":"central","sales":[{"external_id":"check-1001","amount_rub":5400,"occurred_at":"2026-11-08T12:00:00Z"}]}
```

Это **универсальная точка интеграции**, а не готовый коннектор к конкретной версии 1С.

## Конфиденциальность и методология

- Опросы не собирают имена, контакты или идентификаторы устройств. Сервер может обрабатывать IP-адрес технически; организатор обязан опубликовать уведомление об обработке данных с учётом применимого права.
- Камеры и биометрия **не подключены**. Входы можно учитывать внешним обезличенным датчиком, но корректность реальных данных требует калибровки.
- Цифры в демо — синтетические. Рекомендации основаны на правилах; они не являются гарантией прибыли.
- Награда за опрос — просто настраиваемый текст. Реальные скидки/промокоды через POS не выдаются без соответствующей интеграции.
- В приложении отсутствуют анализ лиц, видеоидентификация, скрытый сбор личных данных и обещание «прочитать мысли покупателя».
