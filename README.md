# OSMANX RETAIL INTELLIGENCE

**R0.2 | Рабочая локальная retail-аналитика + терминал на выходе.** Премиальный русскоязычный интерфейс на компьютере и телефоне, безопасный для пилотного тестирования при правильной настройке сервера. В основе FastAPI, SQLite, vanilla JavaScript и CSS, без внешних UI-библиотек и отправки данных сторонним сервисам.

> **Важно:** деморежим содержит **искусственные данные** и открывает административные API без пароля. Не публикуйте `OSMANX_DEMO_MODE=1` в интернете. Прямой коннектор к 1С, реальные камеры и кассовые терминалы **не подключены**. Промышленный мультиарендный SaaS пока не готов.

## Запуск

Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
OSMANX_DEMO_MODE=1 python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:

```powershell
$env:OSMANX_DEMO_MODE="1"
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Административный кабинет: <http://127.0.0.1:8000/>. Публичный опросник на планшет: <http://127.0.0.1:8000/kiosk/central>. Документация API в демо: <http://127.0.0.1:8000/api/docs>.

Чтобы перезапустить демонстрацию с чистой базой, остановите сервер и удалите `data/retail.sqlite3` (только в деморежиме). **Не удаляйте реальную базу магазина.**

## Реализованные функции

| Модуль | Что работает в R0.2 | Ограничение |
| --- | --- | --- |
| **Опросник у выхода** | 4 вопроса: оценка, покупка/причина, что понравилось, что улучшить. Сохранение ответа, защита от повторной отправки. | Опрос добровольный, выборка не репрезентативна автоматически. |
| **Бонус после опроса** | Владелец включает кампанию, система выдаёт уникальный код, сотрудник проверяет и погашает код. | Бонус не связан с POS и сам по себе **не гарантирует скидку**. |
| **Учёт входов и продаж** | Ручные события, идемпотентный API датчика, JSON-импорт чеков, почасовая и подневная аналитика с часовым поясом филиала. | Входы и чеки — разные события; число входов не означает уникальных клиентов. |
| **Тепловая карта зон** | Создание зон, координаты на условной схеме, события от внешнего датчика через API, агрегаты. | Не физический план помещения; камера и сам датчик отдельно не подключены. |
| **Неудовлетворённый спрос** | Фиксация модели, размера и цвета; поиск точного совпадения по остаткам других филиалов, смена статуса с историей. | Запрос не равен гарантированно упущенной продаже. |
| **Подтверждение покупки** | Связь запроса с зарегистрированным чеком, проверка магазина, времени и запрет повторного использования чека. | В реальном магазине нужен импорт чеков из POS. |
| **Склады** | Ручное и пакетное обновление артикулов, остатков и источников данных. | Синхронизация с 1С не подключена. |
| **Пилоты** | Реестр бизнес-гипотез, базовая и измеренная метрики, статусы, комментарии. | Не автоматический причинно-следственный анализ или A/B-платформа. |
| **Кабинет директора** | KPI, доли ответов, графики, источники и предупреждения о качестве данных, экономический сценарий. | Сценарии роста — расчёты, **не обещание результата**. |
| **Экспорт** | CSV: анкеты, спрос, склады, входы, чеки, пилоты; экранирование Excel-формул. | Для реального BI могут понадобиться дополнительная нормализация и согласованные определения. |

## Пять крупных инженерных блоков R0.2

1. **Kiosk OS:** четыре шага, выбор категорий, повторная отправка без дублей, бонусный код и проверка у сотрудника.
2. **Traffic Intelligence:** локальный часовой пояс, дневная динамика, источники, контроль двойного учёта и анонимные зоны на схеме.
3. **Lost Demand & Inventory:** товары по филиалам, сопоставление артикула и размера, журнал запросов, подтверждение состоявшейся продажи чеком.
4. **Director OS:** рабочие экраны, мобильная адаптация, реестр гипотез, CSV-экспорт, методологические предупреждения.
5. **Engineering & Security:** миграции с R0.1, авторизация, валидация, заголовки защиты, API + браузерные тесты, CI.

## Настоящий режим с паролем

```bash
export OSMANX_DEMO_MODE=0
export OSMANX_ADMIN_PASSWORD='YOUR_LONG_UNIQUE_ADMIN_PASSWORD'
export OSMANX_SESSION_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
export OSMANX_INGEST_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(32))')"
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Администратор входит в браузере с паролем, получает подписанную сессию на 8 часов. Сервер требует пароль от 12 символов и секрет подписи от 32 символов. Защищённые API недоступны без Bearer-токена. Публичный терминал не предоставляет административный доступ. Для удалённого использования требуется **HTTPS и проверка безопасности внешнего развёртывания**. Приложение пока рассчитано на одного владельца с несколькими филиалами, а не на независимых арендаторов.

Docker Compose подключает постоянный том `/data` и по умолчанию слушает **только localhost** (`127.0.0.1:8000`), чтобы случайно не открыть незащищённый сервер.

## Интеграция с датчиками и POS

**Датчик входов — только количество:**

```http
POST /api/ingest/traffic
X-OSMANX-Ingest-Key: <private-key>
Content-Type: application/json

{"slug":"central","quantity":2,"external_id":"entry-00001","occurred_at":"2026-11-08T12:00:00Z"}
```

**Датчик активности в зоне:**

```http
POST /api/ingest/zones
X-OSMANX-Ingest-Key: <private-key>
Content-Type: application/json

{"slug":"central","zone_code":"fitting","quantity":2,"external_id":"zone-00001","occurred_at":"2026-11-08T12:00:00Z"}
```

Сначала создайте зону в кабинете. Один и тот же `external_id` в одном источнике не учитывается повторно.

**Импорт чеков (не прямая синхронизация 1С):**

```http
POST /api/admin/import/pos
Authorization: Bearer <admin-token>
Content-Type: application/json

{"slug":"central","sales":[{"external_id":"receipt-001","amount_rub":5490,"occurred_at":"2026-11-08T12:00:00Z"}]}
```

API не принимает изображения, распознавание лиц или биометрические профили клиентов. Перед подключением датчиков проверьте качество измерения, законность их использования, уведомление посетителей и применимые нормы обработки данных.

## Проверки и визуальная приёмка

```bash
pip install pytest httpx playwright
python -m pytest tests -q
python -m compileall -q backend scripts
node --check frontend/app.js
python scripts/visual_smoke.py
```

**21 API/DB-тест** и изолированная браузерная приёмка в Chromium проходят локально. Браузерный тест проверяет настоящий JavaScript/DOM, клики, формы, кросс-филиальный поиск, прохождение опроса, сохранение и экраны шириной 390 px. Он перенаправляет запросы в FastAPI TestClient, поскольку браузер тестового окружения блокирует прямую навигацию на localhost. Это **не замена** финальной приёмки публичного HTTPS-развёртывания и физического терминала.

GitHub Actions запускает тесты при push/PR, устанавливает Chromium и прикрепляет скриншоты к прогону. Статус конкретного прогона следует проверять отдельно.

## Методология и границы ответственности

- В демо все потоки, чеки, оценки, зона активности и остатки синтетические. Состояние «демо» видно в интерфейсе.
- Опросы не требуют имени и телефона. Код бонуса случайный и проверяется вручную; многократные прохождения при желании ещё возможны и требуют физического контроля сотрудников.
- Карта зон отображает суммарные события. Это **не видеоаналитика**, не идентификация людей и не персональный путь покупателя.
- Кассовые чеки и входы не дают строгой персональной конверсии; даже при безошибочных данных один человек может входить несколько раз и покупать несколько раз.
- Для магазинов нужны правовая оценка, политика хранения и удаления данных, резервное копирование, роли и аудит безопасности прежде чем запускать коммерческий сервис.
