# OSMANX RETAIL INTELLIGENCE R1.0 — Executive Experience

Релиз развивает существующую R0.9. Все пять модулей используют общую SQLite-базу,
существующие организации, филиалы, права и события. Стили сохранены: глубокий
тёмно-синий, сдержанный красный акцент, минимализм, русский интерфейс.

**Развёртывание в интернет отложено по требованию владельца.**

## 1. Сравнение филиалов по одинаковой методике

`GET /api/admin/r10/benchmark?days=14&source_mode=sensor`

- Использует только филиалы, разрешённые текущему пользователю.
- Входы одного выбранного типа: `signed_sensor`/`sensor`/`traffic` либо `manual`.
- Исключает демонстрационные источники; помечает расхождения и ручные чеки.
- Показывает **чеки на 100 зарегистрированных входов**, не уникальную конверсию
  и не причинный эффект работы сотрудников.
- До 100 филиалов, окна 7–30 дней; минимальная база для сравнения — 30 входов.

## 2. Планирование смен и нагрузка

`GET /api/admin/r10/shifts` · `POST /api/admin/r10/shifts` ·
`POST /api/admin/r10/shifts/{id}/cancel`

- Смена: филиал, необязательный назначенный сотрудник, рабочее окно,
  плановая ёмкость обслуживания в час и уникальный ключ операции.
- Смена одного сотрудника не может пересекаться с его другой активной сменой.
- Сотрудник должен принадлежать организации и иметь доступ к филиалу.
- Часовой отчёт сопоставляет плановую ёмкость и **фактически записанные** входы.
  Не является прогнозом выручки или характеристикой эффективности сотрудника.
- Создание идемпотентно, повтор с изменённым телом возвращает 409.

## 3. Нормативы помощи покупателям

`GET /api/admin/r10/service` · `PUT /api/admin/r10/service/targets`

- Использует действующие обращения `/api/assist/{token}` и журнал R0.7.
- Срок принятия: 1–60 минут; завершения: 2–180 минут.
- Проценты считаются только среди обращений с известной отметкой времени.
- Показывает медиану, P90, принятые, закрытые и открытые просроченные обращения.
- Нет распознавания личности посетителя, камеры не требуются.

## 4. Короткий анонимный опрос на экране выхода

`GET/POST /api/admin/r10/pulse` · запуск/выключение кампании ·
`GET/POST /api/public/r10/pulse/{slug}`

- Руководитель задаёт вопрос и 2–5 коротких вариантов; **только одна активная
  кампания на филиал**. Результаты сохраняются в SQLite и видны в кабинете.
- В ответе сохраняются идентификатор попытки, номер варианта и время. Нет
  ФИО, телефона, фотографий, персонального видеослежения и свободного текста.
- Обязателен **привязанный планшет** (`/api/admin/kiosks/{slug}/rotate`).
  Секрет передаётся после `#access=` либо `#token=` в ссылке планшета.
  В целях защиты ключ нельзя публиковать в открытом QR-коде для прохожих.
- Публичная отправка требует действующего ключа, имеет ограничение 120 новых
  ответов за минуту на филиал и idempotency-проверку `request_id`.
- Пользователь может пропустить опрос. Система не выдаёт скидку автоматически.
- `python -m scripts.purge_pulse_r10` делает dry-run; `--apply` удаляет
  индивидуальные записи старше `survey_retention_days` магазина (7–365 дней).

## 5. Инциденты качества данных и сервиса

`GET /api/admin/r10/incidents` · `POST /api/admin/r10/incidents/scan` ·
`PATCH /api/admin/r10/incidents/{id}`

- Условия: 3+ чеков без товарных строк за 3 дня, просроченные задачи R0.8,
  просроченная помощь покупателю по SLA.
- Сканирование идемпотентно для каждого дня и филиала.
- Журнал с объяснением и статусами `new → acknowledged → resolved`.
- Опциональное создание одной задачи в существующем центре директора R0.8.
- Подтверждённые/закрытые записи из чужих организаций недоступны; закрытый
  инцидент не переписывается.

## Как посмотреть локально

```bash
pip install -r requirements.txt pytest httpx playwright
OSMANX_DEMO_MODE=1 python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

- Кабинет: `http://127.0.0.1:8000/static/experience.html`
- Опросник: `http://127.0.0.1:8000/static/pulse.html?store=central`
  (необходима привязка планшета и активная кампания)

## Проверки

```bash
python -m pytest tests/test_r10.py -q
node --check frontend/experience.js
node --check frontend/pulse.js
python scripts/r10_browser_smoke.py
python -m compileall -q backend scripts
```

Chromium проверяет создание смены, сохранение норматива SLA, создание и запуск
кампании, сканирование инцидентов, прохождение терминального опроса,
скриншоты на 1440, 700 и 390 px. Действия используют FastAPI TestClient, а не
скриншоты заранее написанных данных. Дополнительно в CI сохранена старая
проверка всех версий и все браузерные сценарии R0.2–R0.9.

## Что **не** готово

Это локальный рабочий релиз, **не коммерческий продакшен**. Физические камеры,
датчики, терминалы и конкретные конфигурации 1С/касс здесь не подключались.
Не реализованы индивидуальное видеослежение, гарантированное увеличение
выручки, автоматические скидки, рассылки и публичное размещение.
Прежде чем обрабатывать настоящие данные покупателей на сервере, нужны
проверка правового основания, уведомления, оценка защиты и испытания техники.
