# OSMANX Retail Intelligence R0.2 — инженерная приёмка

**Статус:** рабочая локальная версия, не публичный коммерческий SaaS.

## Изменения относительно R0.1

| Блок | Изменение | Приёмка |
|---|---|---|
| Kiosk | 4 этапа, категории ответов, idempotency key, опциональные одноразовые коды | API, Chromium |
| Traffic | Local timezone, 7/30 days, sources, warnings, daily chart | API, Chromium |
| Zone map | Named zones, positions, sensor ingestion, aggregated heatmap | API, Chromium |

## Data model

- `stores`: магазины одной административной рабочей области, настройки анкеты, часовой пояс.
- `visits`: агрегированные входы, источник, UTC timestamp, unique external ID.
- `sales`: чеки, копейки, источник, UTC timestamp, unique external ID.
- `signals`: отдельно учтённые «интерес» и «примерка», **не связаны с отдельными людьми**.
- `surveys`: анонимные добровольные ответы + категории; request_id для защиты от сетевого повтора.
- `rewards`: одноразовые ручные коды и отметка погашения; POS-системы не подключены.
- `inventory`: артикулы и остатки по магазинам, источник и дата снимка.
- `demand`/`demand_history`: запросы и история статусов. `sale_id` — единственный признак подтверждённой продажи.
- `zones`/`zone_events`: анонимные события счетчика по конкретной зоне, без сырых изображений.
- `experiments`: проверки гипотез; результат вводится вручную, метрика не рассчитывается AI.

## Слои приложения

- FastAPI: публичная анкета, сервер авторизации, административный API и ingest API.
- SQLite WAL: локальное хранение с индексами, связями и повторяемой миграцией.
- Static vanilla JS/CSS: система без Node.js-сборщика и без внешних подключений для UI.
- Browser QA: реальный Chromium DOM, через перехват `fetch()` к FastAPI TestClient. Возможна настоящая URL-приёмка уже после деплоя.

## Известные ограничения перед продажей как SaaS

1. Нет независимых аккаунтов владельцев, матрицы ролей, сквозного аудита доступа или RBAC.
2. Не подключены 1С, конкретные кассы, камерные SDK, покупательские приложения или реальные датчики.
3. Нет автоматического подтверждения скидки через POS и защиты от массового участия посетителя по нескольким устройствам.
4. SQLite подходит для локальных пилотов, но для коммерческого мультиарендного режима потребуется архитектура данных, HA/backup, миграции и изоляция организаций.
5. Диагностика правил не гарантирует причинно-следственного влияния изменения на прибыль.
6. Нет независимой проверки WCAG, нагрузочного тестирования, внешнего penetration test и финального юридического анализа видеонаблюдения/персональных данных.
