## Самый быстрый запуск

Откройте файл **`OSMANX_EXECUTIVE_OFFLINE.html`** в обычном браузере. Он **полностью автономный**, CSS/JavaScript внутри одного файла, никаких npm и интернета. На Android нужно извлечь ZIP, открыть файл через браузер или локальный просмотрщик HTML. В некоторых мобильных приложениях предпросмотра запуск JavaScript запрещён — тогда используйте обычный браузер или локальный HTTP-сервер.

Для разработки (Python 3 и Node.js 20+):

```sh

# http://127.0.0.1:4173
npm test
python3 scripts/build_standalone.py
```

На Windows: `py -m http.server 4173` и откройте `http://127.0.0.1:4173/`. Ничего устанавливать через npm не требуется.

## Что реализовано

1. **Executive Dashboard** — оборот, себестоимость, валовая прибыль, маржа, повторные покупки, динамика и интерактивная Retail Opportunity Map. Фильтры периода, филиала, категории, размера, модели, три состояния сети.
2. **EXECUTIVE DEMO (30 seconds)** — пять сцен с ручной и автоматической навигацией (5/6/7/7/5 секунд). Воронка 60 → 32 → 18 → 7 и связанные чеки с валовой прибылью 28 000 ₽. Выводы строго разделены на факты/оценки/гипотезы/прогнозы.
3. **Synthetic Event Generator** — 300 товарных моделей, 3 филиала, 90 календарных дней, размеры/цвета, 9 000 комбинаций текущих остатков; продажи и возвраты, трафик, запросы, согласия, примерки, обращения за помощью, перемещения, ревизии, предзаказы и опросы.
4. **10 аналитических модулей** — не карточки-заглушки, а отдельные представления с выборкой событий, метриками и цепочкой «сигнал → доказательства → деньги → действие → результат».
5. **Решения, калькулятор, презентация и диагностика** — приоритизация гипотез, собственные параметры конверсии и затрат, полноэкранный лаконичный режим переговоров, семивопросный опрос и **настоящий PDF из Canvas + встроенного PDF writer**. Данные ответа не уходят в сеть.

## Принципы финансового учёта

- **Факт:** семь связанных чеков на 8 900 ₽ при себестоимости 4 900 ₽ дают `7 × 4 000 = 28 000 ₽` валовой прибыли по этим чекам. Это **не доказанная дополнительная** валовая прибыль.
- **Оценка/гипотеза:** нерешённые запросы × предполагаемая конверсия × средняя маржа. Раскрывается как предположение и требует проверки на реальных событиях.
- **Прогноз перемещения:** `количество × вероятность покупки × (цена − себестоимость) − стоимость логистики`. Сценарий: 3 × 0,55 × 4 000 − 3 × 350 = **5 550 ₽**.
- **Возвраты:** выручка нетто = продажа − возврат; валовая прибыль = выручка нетто − себестоимость реализованного товара с корректировкой на возвращённые позиции.
- **Конверсия по одной категории/размеру:** не вычисляется из общего потока посетителей; отображается `—` до появления релевантной базы.
- **Витрины/примерки:** данные дают наблюдаемые связи, но не доказательство причинной связи и не гарантированную прибыль.

## Техническая структура

```text
index.html                        — модульная версия для HTTP
OSMANX_EXECUTIVE_OFFLINE.html     — версия одного HTML для офлайн-показа
src/model.mjs                     — связанные синтетические данные и финмодель
src/ui.mjs                        — графики SVG, воронка, исходные события
src/app.mjs                       — состояние, маршруты, 10 модулей, демо, опрос
src/pdf.mjs                       — клиентский PDF без зависимостей
src/r3_core.mjs                   — доказательная финансовая сверка, перемещения, пилоты, журнал, CSV
src/r3_views.mjs                  — четыре связанных executive-экрана
src/r3.css                        — новые премиальные адаптивные стили
src/styles.css                    — Obsidian Executive + ATELIER luxury-слой, адаптивный дизайн
assets/icon.svg                   — фирменный значок
scripts/build_standalone.py       — сборка единого HTML
scripts/browser_smoke.py          — Chromium 390/768/1440/1920 и PDF
scripts/r3_browser_smoke.py       — новые пути, CSV, persistence, 4 viewport
scripts/static_preview.mjs       — вспомогательная статическая QA-копия
scripts/                           — сборка и проверка
.github/workflows/                — пример CI для автономного слоя
tests/                            — финансовые и сценарные тесты
```

**Стек в этой версии:** нативные ES-модули JavaScript, CSS, SVG и Canvas без runtime-зависимостей. Почему не React/Vite: существующий основной продукт уже обслуживается FastAPI со статическим `/static`, а в среде сборки нет доступа к npm-реестру. Нативные модули позволяют дать проверяемый офлайн-продукт сегодня, не нарушая существующую систему. Выделенные слои данных/вида/контроллера могут быть позднее перенесены на React/TypeScript без изменения расчётных правил.

Серверная часть прежнего проекта остаётся неизменной. Демо **не подключено** к реальной 1С, персональным данным, PostgreSQL, приборным счётчикам или POS. Не публикуйте существующий demo-mode FastAPI как публичную службу: у R0.7 есть собственные ограничения безопасности. Этот HTML безопасно просматривать отдельно как демонстрацию, но он не обеспечивает авторизацию и изоляцию данных настоящих клиентов.
