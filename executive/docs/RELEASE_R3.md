# ATELIER R3 — пять полноценных блоков реализации

**Продукт:** OSMANX RETAIL INTELLIGENCE · Executive Edition. 8 ноября 2026 г.

**Статус:** автономная локальная демонстрация на синтетических данных. Сохранены дизайн ATELIER R2, 30-секундный маршрут, 10 аналитических модулей и полный существующий backend R0.8. Ни одна «кнопка проверки» не отправляет реальное сообщение, не резервирует остаток и не выполняет запись в 1С.

## 01 — Финансовый реестр и связанная доказательная цепочка

`src/r3_core.mjs::reconcileEvidence(dataset, scope)` пересчитывает нетто-выручку, чистую себестоимость и валовую прибыль из ID чеков и возвратов. Проверяет ссылки возвратов на исходные продажи, модели, размеры и филиалы; воронку запрос → связанную продажу — по ID, модели, размеру, магазину и хронологии. Учитывает возвраты в периоде независимо от даты продажи. Страница «Проверка цифр» раскрывает первичные строки. **28 000 ₽ — валовая прибыль по семи связанным чекам; доказательство дополнительности отсутствует**.

## 02 — Проверяемый межфилиальный план

`planTransfer` использует реальную (в рамках демоданных) модель, размер, цвет, филиал-отправитель и получатель, snapshot остатков, дату, незакрытые запросы за последние 14 дней. Отклоняет план без доступной единицы, без спроса, с совпадающими филиалами, завышенным количеством, некорректной вероятностью или логистикой и устаревшим снимком. Прогноз рассчитывается из цены, себестоимости, вероятности покупки и обоих типов затрат.

Пример AURA/L/графит: в филиале №2 учтены 3 шт., в филиале №1 — 0; 7 незавершённых запросов; `3 × 0,55 × (8 900 − 4 900) − 3 × 350 = 5 550 ₽` **сценарного эффекта, не подтверждённой дополнительной прибыли**. Пользователь может сохранить **план проверки**, а не исполнить перемещение.

## 03 — Пилот и неопределённость

`evaluatePilot` сравнивает реально выбранную синтетическую выборку обращений и связанных чеков с **введённой собственником** контрольной группой. Пока контроль не введён, финансовый эффект сравнения не вычисляется. При валидных контрольных событиях рассчитываются доли, разность долей, описательная валовая прибыль и после затрат, 95%-е интервалы Wilson. Поля контрольной группы обновляются при каждом вводе с восстановлением фокуса; результат всегда маркируется как **описательный**, а не доказанная причинность: нужно сопоставлять группы, сезонность, акции и издержки.

## 04 — Локальный реестр решений

`newJournalEntry / transitionJournal / restoreJournal / journalCsv`: полный цикл «создано → в работе → измерено → закрыто», ограничения допустимых переходов, ID и связанные исходные события **из соответствующего модуля**. Для результата нужны четыре валидных поля: до/после/выборка/расходы. Сохраняется только локальная версия журнала в браузере (ключ `osmanx-executive-r1`, schema `journal.version=1`) без передачи клиентских контактов. Есть безопасный CSV-экспорт с экранированием формул. Никакой статус не означает доказанный прирост.

## 05 — Инженерная приёмка и доступность

Маршруты открываются из компактного блока главного экрана и скрываемого меню; первые 30 секунд остались свободны от перегрузки. Новые экраны адаптируются к 390/768/1440/1920 px, содержат явные source labels, keyboard-focus, skip-link, reduced motion и монотонную типографическую иерархию.

`npm test` — **56/56 локальных автоматических тестов**: исходные 30 + 26 R3. Тесты охватывают целостность финансовых событий, stock constraints, сравнение с контролем, ограничения и переходы журнала, защиту CSV, навигацию. Браузерная QA: `python3 scripts/browser_smoke.py` и `python3 scripts/r3_browser_smoke.py`, сценарии для 4 размеров, последовательность управления, CSV, PDF, persistence и проверка overflow. GitHub Actions запускает оба набора сквозных проверок на Linux/Chromium с сохранением скриншотов.

### Сборка и запуск

```bash
# Из директории executive/
python3 scripts/build_standalone.py
npm test
python3 -m http.server 4173 --bind 127.0.0.1
# http://127.0.0.1:4173/
```

Для разовой демонстрации без Node/Python откройте `OSMANX_EXECUTIVE_OFFLINE.html` в браузере. `frontend/executive.html` — такая же самодостаточная копия, которую FastAPI обслуживает через `/static/executive.html`. Публичная публикация backend не производится.

### Ограничения качества

Локальный тест Chromium для текущего сеанса заблокирован административной политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`); также не установлена совместимая Playwright-поставка браузера. Поэтому визуальное соответствие на реальных экранах **не заявляется как локально проверенное**. CI в GitHub проверяет браузер отдельно. До успешного CI/ручного сравнения не объединять изменения автоматически с основной веткой.

Все данные синтетические: нет реальных контактов, реальных датчиков, реальной 1С, фактических резервов, PostgreSQL и публичного SaaS. Финансовый «факт» в интерфейсе означает факт **в синтетическом реестре**, а не подтверждённую коммерческую пользу.
