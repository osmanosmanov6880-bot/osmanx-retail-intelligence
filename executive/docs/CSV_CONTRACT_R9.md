# ATELIER R9 — контракт платёжных источников

R9 является только **локальным сравнением выгрузок, предоставленных пользователем**. Ни 1С, ни банк, ни POS автоматически не подключаются. Настоящую банковскую выписку можно загрузить после удаления из неё персональных данных и прочих секретов. Совпадение полей — не подтверждение подлинности выписки.

## Зависимость от R8

Сначала загрузите R8 `sales` (обязательно), `returns` (если есть возвраты). В коде `R9` используются только ссылки `referenceId`, `saleId` и дата/филиал из этих проверенных таблиц. `requests` и `stock` для платёжной сверки не нужны, но остаются доступными в других модулях.

Изменение любого CSV в R8 полностью сбрасывает R9-операции и разбор исключений. При обновлении страницы все R8/R9 строки исчезают. Технические ID не должны содержать ФИО, телефон, email или адрес.

## 1. `operations`

Первая строка, строго в этом порядке:

```
id;date;storeId;kind;referenceId;amount;fee;method;batchId
```

- `id` — уникальный технический идентификатор операции.
- `date` — дата записи операции в `YYYY-MM-DD`, не позже 2026-11-08 (фиксированная дата демоверсии).
- `storeId` — тот же филиал, что у чека/возврата R8.
- `kind` — только `capture` (оплата по `sales.id`) либо `refund` (выплата по `returns.id`).
- `referenceId` — ID первичного чека для capture, ID документа возврата для refund. Недостающие ссылки помечаются аномалиями, а не считаются оплатой соответствующего чека.
- `amount` — строго положительная сумма в рублях, максимум два десятичных знака и не более 1 млрд ₽.
- `fee` — комиссия в рублях, от 0 до `amount`, до двух десятичных знаков.
- `method` — `card` или `cash`.
- `batchId` — обязателен для `card`; для `cash` должен быть пустым, комиссия `cash` равна 0.

Допускается несколько операций для одного чека (например, часть суммы картой, часть наличными). Суммы сверяются **в копейках**. Отрицательные выплаты **не** вводятся как отрицательная `amount`: тип `refund` меняет направление потока.

## 2. `settlements`

```
id;date;storeId;batchId;netAmount
```

- `id` — уникальная строка банковского поступления.
- `date` — дата зачисления или списания по предоставленной выписке, `YYYY-MM-DD`.
- `storeId` и `batchId` — составной ключ пакета операций карты.
- `netAmount` — подписанная сумма в рублях, до двух десятичных знаков (возврат может дать отрицательное значение).

Сумма пакета: `Σ capture.card.amount − Σ refund.card.amount − Σ card.fee` по `storeId` + `batchId`. Пакеты могут состоять из нескольких операций и нескольких строк выписки. Задержка измеряется от даты **последней** операции до **последней** связанной записи выписки.

**Важное ограничение:** нет подтверждения счёта банка, идентичности владельца, банковского settlement-ID, chargeback, НДС и иных бухгалтерских проводок. Файл без строки зачисления означает **отсутствие свидетельства**, а не доказанный ущерб.

## Формат и безопасность

- UTF-8 (BOM разрешён), кавычки RFC-4180, разделитель `;`/`,` по парсеру R5; максимум **1500 строк**, **1,2 МБ** на файл.
- Любая неверная строка блокирует замену **всего** файла, предыдущая версия остаётся в памяти.
- ID / batch / метод не могут содержать формулы таблиц или HTML; числовые колонки не принимают экспоненту или более двух десятичных знаков.
- CSV-экспорты защищены от formula injection; финансовые вычисления не изменяют файлы и данные R8.
- История собственника сохраняет только количество документов, расхождений, комиссию, статус и некриптографический хеш. Это **не цифровая подпись** и не финансовый аудит.
- До продуктивной эксплуатации требуются реальные системные даты, проверка доступа, независимая сверка источников и регламент обработки персональных данных.
