# OSMANX RETAIL INTELLIGENCE — ATELIER R8

Дата: 2026-11-08. Ветка: `feature/executive-r2-atelier`, PR #9. Не публикация в production.

## Назначение

R8 — первый сквозной **локальный рабочий режим для собственных обезличенных CSV**, а не очередная синтетическая панель. R8 изолирован от 90-дневной синтетической модели и текущего серверного приложения. При обновлении страницы исходные CSV исчезают из оперативной памяти, пользователь должен загрузить их повторно. Автоматической интеграции с 1С и доступа к реальному POS нет.

## Пять реализованных больших блоков

1. **Local Source Vault.** Четыре строгих контракта `sales`, `returns`, `requests`, `stock` с SKU вне демокаталога; допустима загрузка файла и вставка CSV, проверка заголовков, типов, точных дат, PII-колонок, дублей, отрицательных значений, связанных чеков, частичных возвратов, актуальности остатков. Файл принимается атомарно: любая ошибка блокирует *всю* замену. Неизвестные поля не подмешиваются. Учебные и локальные CSV не смешиваются, перезапись и стирание требуют отдельного действия.
2. **Verified Cashflow.** Пересчёт валовой прибыли по импортированным продажам и частичным возвратам: `netRevenue = Σ revenue − Σ refund`, `gross = netRevenue − (Σ cost − Σ restoredCost)`. Филиальный разбор и CSV. Показатели — наблюдения в файле, но не внешний финансовый аудит.
3. **Availability Engine.** Только явный нулевой остаток в точке спроса и текущий снимок источника; отсутствие строки != ноль. Товары не распределяются дважды. Прогнозная маржа SKU рассчитывается из импортированных чеков; без чеков денежной оценки нет. Расходы и вероятность регулируются; экспорт маршрутов и создание задачи без передачи сырых строк.
4. **Consent-safe Recovery Pilot.** Только обращения с `consent=1` и без связанного чека; детерминированное 2-рукавное тест/контроль разбиение, параметры доли, максимума обращений, предположительного uplift и затрат. Нет связи с контактами, сообщений и автоматических отправок. Отчёт показывает, если выборка мала; формулы не объявляются доказанным инкрементальным эффектом.
5. **Director Sign-off.** Пять утверждений с эпистемическим статусом, CSV и настоящий A4 PDF, выбор управленческого статуса, локальная агрегатная история до 40 записей, цепочка контрольных сумм с проверкой восстановления и отказом при подмене. История не содержит ID чеков, запросов и контактов. Контрольная сумма FNV-1a не является криптографической подписью.

## CSV-договор

UTF-8 / BOM, разделитель `;` или `,`, RFC-4180 кавычки, до 1,2 МБ/1500 строк на таблицу. Обязательный порядок столбцов (регистр чувствителен):

- `sales`: `id;date;storeId;sku;size;units;revenue;cost` — денежные значения это сумма по строке.
- `returns`: `id;date;saleId;units;refund;restoredCost` — в пределах оплаченных количеств, выручки и себестоимости.
- `requests`: `id;date;storeId;sku;size;consent;linkedSaleId` — `consent` только `0`/`1`, `linkedSaleId` может быть пустым.
- `stock`: `id;asOf;storeId;sku;size;quantity` — уникальный снимок по дате/магазину/SKU/размеру.

В реальных CSV должны использоваться **только обезличенные технические ID**, не ФИО, телефон, адрес, аккаунт или email. Защита проверяет типы и столбцы, но не может доказать отсутствие персональных данных внутри произвольных идентификаторов: пользователь обязан обезличить файл до импорта.

## Упрощённый запуск

1. Откройте `executive/OSMANX_EXECUTIVE_OFFLINE.html` в современном браузере или `python3 -m http.server 4173` внутри `executive/`.
2. Откройте меню → ATELIER R8 → CSV: локальная приёмка.
3. Для учебной проверки используйте «Загрузить учебный набор» (он явно помечается как пример) или принимайте ваши локальные CSV в порядке: чеки → возвраты → запросы → остатки.
4. Проверьте сверку, наличие, пилот и экспорт директора. Для смены между учебными и рабочими файлами нажмите «Очистить рабочий набор».
